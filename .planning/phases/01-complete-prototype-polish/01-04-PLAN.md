<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → mcp.swiggy.com/im | fetch POST with Bearer token; JSON-RPC; OAuth 2.1 required |
| Browser → swiggy.com (window.open) | New tab navigation; no data passes cross-origin |
| User input → Swiggy token field | Text input from donor; used as Bearer token value |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | Swiggy OAuth token input | mitigate | Token is only sent to `mcp.swiggy.com` via HTTPS; field is `type="text"` not `type="password"` — acceptable for demo prototype where the token is a demo-mode entry, not a production secret |
| T-04-02 | Spoofing | window.open to swiggy.com | mitigate | `window.open(url, "_blank", "noopener,noreferrer")` — opener reference isolation prevents the opened tab from accessing the NeedFeed window object |
| T-04-03 | Tampering | pledgeCtx.item used as Swiggy search query | accept | Item name comes from mock HOMES data (controlled); not user-freeform input in this prototype; low injection risk |
| T-04-04 | Information Disclosure | Swiggy token in component state | accept | Token is session-only in useState; not persisted; not logged; demo-mode only; acceptable for prototype |
| T-04-05 | Denial of Service | Repeated callSwiggyMCP calls on retry | accept | No rate limiting implemented; prototype only; retry is user-initiated button click |
| T-04-SC | Tampering | npm installs | accept | No new packages; lockfile unchanged |
</threat_model>
